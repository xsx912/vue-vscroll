# 头部插入锚定：O(1) 纯前插探测，块高修正

向上加载历史（聊天、时间线）时，头部插入 N 条会使全体索引平移——锚定若仍按"旧首索引 ↔ 新同索引偏移"比对会错行。我们决定：组件侧 O(1) 探测**纯头部插入**（原首条原位后移 N 位），命中则以**插入块总高**修正 scrollTop，当前视图纹丝不动；探测手段按模式选择——动态模式必须身份键（`getItemKey`，索引平移否则测量错位，ADR-0005 地基），定高/已知变高用对象引用比对免键，原始值数组无键时跳过（值相等会误判）。修正量的高度取探测时刻的已知高度（已测 ?: 估算），后续测量落地由既有 delta 锚定继续跟进。

已知边界（接受）：只保证纯头部插入，混合变更（头尾同时追加）探测失败回落既有锚定；已知变高的纯索引型 `itemSize(i)`（行高只看索引不看数据）前插后映射漂移，属契约内；测量提交与 items 变更同 flush 合并时，该批测量的锚定增量被前插修正吞掉（rAF 与 Vue flush 分属不同任务链，概率极低）。前插使两阶段跳转的索引语义失效：消费前插修正时清空跳转意图。容器声明 `overflow-anchor: none`，防浏览器原生滚动锚定与虚拟列表的自修正双重补偿。

## Consequences

- "向上加载历史"的推荐配置：`getItemKey` + 动态测量（或定高免键）；文档写明各模式的探测手段。
- 修正量的 consume-once 通过 `prependShift()` 闭包传递，依赖组件侧 watcher 先于状态机 offsets watcher 注册（同组件创建序即执行序），注释已标明该时序约束。
