# VGrid 独立组件：复用纵向内核，列固定宽，v1 不做横向虚拟化

虚拟表格（多列网格）做成独立 `VGrid` 组件，而不是往单轴的 VScroll 里塞列概念。理由：VScroll 的行高三分模式（固定/已知变高/动态测量）是单轴语义，网格的行高由列内容聚合、测量语义完全不同——共用一个组件会逼出双轴耦合的 props 语义。VGrid 复用 `useVScroll` 纵向状态机与 `computeWindow` 乘法捷径（行高固定），触底哨兵与容器视口测量抽成共享组合函数（`useLoadMoreSentinel` / `useContainerViewport`）。

列不虚拟化（v1）：列宽为固定像素数组，总宽超出容器时横向自然滚动。横向虚拟化只在列数极大（百列级宽表）才有收益，而它需要列方向的窗口计算与列偏移管理——不为暂无真实需求的场景引入复杂度；入路线图。已知取舍：`rowSize` 非响应式（与 VScroll 的 `itemSize` 契约一致），运行时密度切换请用 `:key` 重建；头部插入以对象引用探测（定高块高 = n × rowSize，精确），原始值行数组不可靠探测、跳过。空列表时哨兵必在视口内，首个真相交即触发 `loadMore`——可用作首屏回填（与 VScroll 契约一致），需防循环由消费方用 `loading` 把控。

## Consequences

- 未来横向虚拟化落地时，VGrid 的 props 形态（`columns` 数组）可平滑升级为按需传入列窗口回调，不需要破坏性变更。
- 网格的动态行高（行内容聚合测量）是独立的新模式，若做需要新的测量语义，不复用 VScroll 的行测量。
