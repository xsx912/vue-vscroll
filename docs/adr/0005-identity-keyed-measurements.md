# 身份键测量：getItemKey 可选提供，索引键保持默认

测量缓存按什么归属？ADR-0003 选择了索引键（零成本、追加场景正确），代价是整批替换数据后旧行高残留、需要用户显式 `reset()`。现在把代价收回来：新增可选 `getItemKey: (item, index) => string | number`，提供时测量按身份键归属——替换、重排数据时测量自动跟随条目。

为什么保持索引键为默认：身份键要求每行调用一次用户函数（10 万行 = 10 万次调用），而多数场景（追加式信息流、固定数据浏览）索引键完全够用；把成本留给真正需要的场景（换筛选条件、聊天历史重排）。键的唯一性不做运行时检查（O(n) 成本）：契约写在文档，重复键后写覆盖。测量键在 ResizeObserver 回调时即刻落定而非帧提交时——items 在回调与 rAF 之间被替换/缩短时，避免错归属或越界崩溃。

## Consequences

- "换数据后高度不对"的标准答案变为：能提供稳定唯一键就传 `getItemKey`，否则 `reset()`。
- 头部插入（向上加载历史）以身份键为地基：索引平移不再错位测量。
