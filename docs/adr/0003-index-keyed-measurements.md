# 测量按索引键存储，跨 items 变更保留，reset() 显式清空

换数据、追加、重排时，已测行高怎么处理？我们决定：测量按索引归属，`items` 变化（包括引用变化）**不**清空测量缓存；整批替换数据由用户显式调用 `reset()`。理由：追加（loadMore 的 `[...old, ...new]`）也产生新数组引用，若引用一变就清空，会把完全有效的测量丢掉，追加瞬间列表抖动——这是高频场景。代价：替换数据后旧行高残留（索引 i 的测量套在新条目上），文档写明"整批换数据先 reset()"。按条目身份对齐的可选 `getItemKey` 记入路线图，待真实需求出现再做。

## Consequences

- "换数据后高度不对"的用户报告，第一响应是引导 `reset()`，而不是改缓存策略。
