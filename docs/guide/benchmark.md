# 性能基准

实测环境：Chromium，10 万条定高（50px）数据，视口 600px。

| 指标 | 验收线 | 实测 |
| --- | --- | --- |
| 渲染 DOM 节点数 | 恒定（可视 + overscan） | ✅ 顶部 17、滚动中 22 |
| 滚动帧率 | 60fps | ✅ 60–61fps |
| 首屏渲染 | < 100ms | ✅ 1–7ms |
| 主线程长任务 | < 16ms | ✅ 0 次 |

## 在线复测

项目内运行 `npm run dev` 后访问基准页（dev server 的 `#bench` 路由）：
- 实时显示：数据量、渲染 DOM 数、首屏渲染耗时、近 60 帧平均帧率、长任务计数
- 操作：「跳到第 50000 条」验证程序化定位，「回到顶部」复位
- 滚动时观察「渲染 DOM 数」——不随数据总量增长，只随窗口位置在 17–22 之间浮动

## 方法论

- DOM 数由 MutationObserver 在每次窗口变化后重新统计 `.vscroll-item` 节点
- 帧率 = 近 60 帧平均帧间隔的倒数（非瞬时值）
- 首屏渲染 = 组件挂载前 `performance.now()` 到两帧稳定渲染的耗时（覆盖子组件挂载阶段）
- 长任务由 `PerformanceObserver('longtask')` 采集
