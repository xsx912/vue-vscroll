# 性能基准

## 固定行高（10 万行 × 50px，视口 600px）

实测环境：Chromium。

| 指标 | 验收线 | 实测 |
| --- | --- | --- |
| 渲染 DOM 节点数 | 恒定（可视 + overscan） | ✅ 顶部 17、滚动中 22 |
| 滚动帧率 | 60fps | ✅ 60–61fps |
| 首屏渲染 | < 100ms | ✅ 1–7ms |
| 主线程长任务 | < 16ms | ✅ 0 次 |

## 动态高度（10 万行，行高 36–108px 由内容决定，测量模式）

实测环境：Chrome headless（新模式），生产构建，`scripts/bench-acceptance.mjs` 驱动。

| 指标 | 验收线 | 实测 |
| --- | --- | --- |
| 渲染 DOM 节点数 | 有界且与数据量无关 | ✅ 采样 46 次，区间 [13, 18]（上界 = 视口/最矮行 + 2×缓冲 = 27） |
| 滚动帧率 | ≥ 55fps | ✅ 60fps（滚轮连续滚动，含回滚已测区域） |
| 首屏渲染 | 无恶性长任务 | ✅ 14–22ms |
| 主线程长任务 | 最长 ≤ 100ms | ✅ 最长 ≤ 64ms（计数随机器负载波动 0–8 次，属 GC/调度噪声；同一构建零负载轮次为 0 次） |

变高模式的窗口行数随视口内行高混合比浮动（矮行多 → 行数多），属几何必然；「恒定」的承诺是**有界、且不随数据总量增长**。两阶段跳转在真机验证：跳转 50000 后落点被测量修正到真实位置。

### 自动化验收

```bash
npm run build
npx vite preview --port 5212
node scripts/bench-acceptance.mjs   # 需要 Chrome/Edge（可 BROWSER_PATH 指定）
```

脚本驱动页面自身的指标面板（见下方方法论），覆盖：动态模式挂载、两阶段跳转、滚轮连续滚动（下行 + 回滚已测区）、二次跳转，期间采样 DOM 数。帧率/DOM/恶性长任务任一门楣不过则非零退出。

## 在线复测

项目内运行 `npm run dev` 后访问基准页（dev server 的 `#bench` 路由）：

- 模式切换：**固定行高 / 动态高度（测量）** 并列，指标面板随切换重置，只统计本次运行
- 实时显示：数据量、渲染 DOM 数、首屏渲染耗时、近 60 帧平均帧率、长任务计数
- 操作：「跳到第 50000 条」验证两阶段跳转，「回到顶部」复位（动态模式下会同时清空测量）
- 滚动时观察「渲染 DOM 数」——不随数据总量增长

## 方法论

- DOM 数由 MutationObserver 在每次窗口变化后重新统计 `.vscroll-item` 节点
- 帧率 = 近 60 帧平均帧间隔的倒数（非瞬时值）
- 首屏渲染 = 组件挂载前 `performance.now()` 到两帧稳定渲染的耗时（覆盖子组件挂载阶段）
- 长任务由 `PerformanceObserver('longtask')` 采集
